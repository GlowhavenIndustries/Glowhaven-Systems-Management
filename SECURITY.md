# Security Policy

## Reporting a vulnerability

Please do not open a public GitHub issue for a security vulnerability.

Use GitHub's private vulnerability reporting flow when it is enabled for this repository:

**Repository → Security → Report a vulnerability**

Do not include passwords, API keys, session cookies, private certificates, or production credentials in a report.

## Include

- Affected component
- Reproduction steps
- Expected and actual behavior
- Security impact
- Relevant logs or proof of concept when safe

Please allow maintainers reasonable time to investigate and remediate a privately reported issue before publishing exploitation details.

## Scope

Reports involving authentication, authorization, session security, agent authentication, remote operations, injection, SSRF, path traversal, secret exposure, container isolation, or dependency vulnerabilities are especially useful.

Test only systems you own or are explicitly authorized to assess.
